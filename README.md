# النظام المدرسي المتكامل: الأساس (Foundation)

هذا الإصدار الأول من هيكل المشروع ومخطط قاعدة البيانات الأساسي، مبني على الوثيقة المرجعية الموحدة.

## ما فيه

```
db/migrations/   001–009: الامتدادات، الهيكل، الهوية، الصلاحيات، التدقيق، الطلاب، RLS، الأذونات، البيانات المرجعية
db/tests/        اختبارات قاعدة البيانات (تُلغى كلها بـ ROLLBACK)
apps/api/        هيكل NestJS: اتصال قاعدة البيانات بسياق الطلب (RLS) + فحص الصحة
scripts/         migrate.sh (يطبّق الهجرات مع بصمة لكل ملف)
infra/           تهيئة PostgreSQL (إنشاء أدوار التطبيق)
docker-compose.yml  Postgres, Redis, RabbitMQ, MinIO, Keycloak (للتطوير فقط)
```

## التشغيل المحلي

```bash
cp .env.example .env        # غيّر كل كلمات المرور
make up                     # تشغيل الخدمات
make migrate                # تطبيق الهجرات (بحساب المالك)
make test-db                # اختبارات قاعدة البيانات
```

## ما يفرضه المخطط على مستوى قاعدة البيانات

| القاعدة | التنفيذ |
|---|---|
| لا حذف نهائي | trigger يمنع DELETE، وحساب التطبيق بلا صلاحية DELETE |
| عزل الفروع | Row-Level Security بحسب `app.campus_id` |
| سجل تدقيق لا يُعدَّل | سلسلة هاش + منع UPDATE/DELETE/TRUNCATE، والكتابة عبر دوال SECURITY DEFINER فقط |
| مربي صف لشعبة واحدة | فهرس فريد (`homeroom_staff_id`, `academic_year_id`) |
| طالب في شعبة واحدة | قيد استبعاد على مدى التواريخ |
| أرقام الهواتف مغلقة عن التطبيق العام | جدول `person_contacts` بلا صلاحية للدور `school_app`، ويُقرأ عبر `school_contact_svc` مع `log_contact_reveal` |
| دور حساس (مدير فرع) | يتطلب مدة وسبباً ومانحاً، ولا أحد يمنح نفسه |
| أدوار حساسة تحتاج شخصين | `change_requests` (الطالب ≠ المؤكِّد)، و`delegations` (معتمد ثانٍ إلزامي) |

## ما لم يُنفَّذ بعد (بالترتيب المعتمد)

1. ربط الأدوار بالصلاحيات (`role_permissions`) وفق مصفوفة الأدوار v1.3.
2. وحدات المرحلة 1: القبول، الأكاديمي والجداول.
3. المراحل 2–5.
4. تطبيق الويب (Next.js)، والمزامنة المحلية–السحابية، وتكامل Keycloak.

## تنبيهات مهمة

- **لم تُشغَّل هذه الملفات على قاعدة بيانات حية** عند كتابتها (لم تتوفر PostgreSQL في بيئة الكتابة). شغّل `make migrate && make test-db` أولاً، وأصلح أي خطأ يظهر قبل البناء فوقها.
- لا تتصل واجهة البرمجة بحساب المالك أبداً (المالك يتجاوز RLS). استخدم `APP_DATABASE_URL`.
- تشفير الهويات والهواتف وبصمة الهاش (HMAC) تُحسب في التطبيق، والمفاتيح تُدار خارج قاعدة البيانات (KMS/Vault).
- كلمات المرور في `.env.example` أمثلة فقط.
